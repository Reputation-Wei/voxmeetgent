# ADR-002：持续倾听、按请求回答与文本触发语音回复

- 状态：已接受
- 日期：2026-09-29

## 决策

主要语音交互采用 Gemini Live 实时音频流：会议期间持续上传麦克风音频以保持上下文，Agent 默认静默，只有用户明确点名并提问（如“Agent，你怎么看？”、“Hey Agent, what do you think?”）时才回答，不需要先独立说唤醒词。客户端检测插话后立即停止播放和清空待播队列；服务端 `interrupted` 事件用于同步模型回合并再次清除旧音频。保留只发送本地转写文本的文本触发模式。

## 原因

用户需要实时反馈和可打断交互。`cuppibla/live-dj` 展示了本地 RMS 即时停播与服务端打断事件结合的实现方式。

## 后果

实时主模式整场会议持续上传麦克风音频，必须先取得必要同意。需处理回声、假打断、会话恢复和持续音频计费。耳机环境已初步实测本地停播与服务端中断事件配合；长会话和扬声器回声仍未验收。文本模式可用于隐私/成本敏感场景。
